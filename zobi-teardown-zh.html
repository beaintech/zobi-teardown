01 Zobi 是什么

一家应用型 AI 实验室，在做"有情商（EQ）的模型"——训练模型去理解并影响人。

基地

爱沙尼亚塔林。小而扁平的团队——8 个岗位空缺，没有管理层级，所有人直接向创始人汇报。

不是 SaaS 厂商

他们自己训练模型，并为电商品牌端到端跑销售对话。产品就是模型 + 那个闭环。

核心押注

"语言模型靠阅读学会了写作。下一个能力是靠试错和后果学会的——从结果里学，不是从指令里学。"

"没有任何模型学会过销售。前沿模型能把产品描述得完美，但它们从没和一万个别犹豫的买家坐在一起过。"

03 AI 实验室怎么训练模型

实验室的核心引擎：把每一场真实对话变成训练信号。

1 · 跑
agent 为品牌端到端跑真实销售对话
→
2 · 打标签
每条对话贴上结果标签（客户做了什么）
→
3 · 训练
按结果训练，不是按文字。预测每条回复的转化
→
4 · 打分
按"每条对话的收入"评估
↺
5 · 验证
实时留出组 A/B → 部署更好的策略 → 重复
"在结果上训练，在收入上评估。"——模型学的那个信号公开互联网没有：真实买家下一步做了什么。

打分细节：每条草稿回复都会拿到一个转化概率预测；预测和现实的差距回流进训练。读起来最好的回复往往不是卖出去的那条——所以他们从不按"看着好"打分。

04 结果标签（无需人工标注）

没人给回复打分。标签就是客户做了什么——这很难造假。

每条对话记录

  • 回复了——多快回复的
  • 点了链接
  • 买了——多少钱、用没用折扣
  • 之后复购了没有
  • 退款了没有

真实例子（已公开）

"比便宜那款值得吗？"
"说实话，日常用的话值得。这款是大家会复购的。要我帮你留一件吗？"

这就是公开网络造不出来的数据集：100 万条销售对话，每条都带着结果。

05 Zobi 销售 agent — 功能逻辑

agent 处理四类电商场景，然后对每个场景跑同一套循环：

弃单挽回 物流问题 复购提醒 追加销售
触发
真实事件拉起 agent——弃单、物流疑问、该复购了、追加销售窗口
读上下文
首单还是复购 · 是否价格敏感 · 上次购买 · 偏好渠道 · 时段
生成 + 预测
写回复，同时预测它的转化概率
渠道发送
WhatsApp / Email / Web——客户在哪回就在哪发
捕捉结果 → 标签
客户做了什么，变成训练信号
对比 + 验证
预测 vs 实际 → 训练；实时留出组确认真实提升

06 agent 真正学到了什么

"销售多半不在话里。"——从薄弱信号读懂人，把时机找对，知道什么时候该闭嘴。

薄弱信号

  • "你最好了 🙏" → 对话是热的
  • "ok" → 对话在降温
  • 什么时候提价格
  • 什么时候跟进
  • 什么时候该安静

上下文改变回复

  • 老客户 + 折扣 = 白白让利
  • 犹豫的首单，周日晚上 + 折扣 = 有时能成单
  • 折扣能赢单也能拉低品牌
  • 模型是靠大量见过才学会的——不是靠规则

伦理内建：同意、语气、诚实是被测量的，不只是护栏——"丢了这个客户的单，不叫赢。"

07 差距：他们的模型 vs 我们的 API

Zobi — 模型自己拥有

  • 在 100 万+ 带结果标签的销售对话上训练
  • 学的是后果，不只是文字
  • 每条回复预测转化
  • 每场实时对话都在变强
  • 护城河 = 数据飞轮 + 自有权重

我们 — DeepSeek / Kimi / 混元 API

  • 在公开互联网上训练，从没见过销售结果
  • 能写流利的销售文案，但不知道有没有用
  • 没有转化预测，没有结果学习
  • 两次调用之间是一成不变的
  • 护城河只能来自我们的闭环，不是权重

核心差距：API 模型缺了"结果反馈闭环"。我们没法重训它——但我们可以在它外面把闭环建起来。注意：混元（Hunyuan）是腾讯自研模型，但作为 API 调用时，和 DeepSeek / Kimi 一样没有 outcome 数据，差距同样存在。

09 我们怎么补差距

模型 = 写手。我们的闭环 = 老师。六个具体机制：

1 · 结果标签

Zobi 的标签 = 客户实际做了什么（回复 / 点击 / 购买 / 复购 / 退款）。放到销售管道里同理：回复 → 预约（Calendly）→ 到场 → 要报价 → 接受。Pipedrive 正好支持：阶段可自定义、官方就建议以「可观察的客户里程碑」来定义，API 可移动阶段、webhook 在阶段变化时触发——标签能自动写回。[zobi.com · support.pipedrive.com · developers.pipedrive.com]

2 · 每条对话的收入

Zobi 的北极星：每条对话的收入，从不按"读着顺不顺"打分。我们也一样：成交时收入落定，成交前标签就是上面的客户动作。[zobi.com]

3 · 上下文靠记忆

Hermes 持久记忆存首单/复购、价格敏感、渠道、时段。

4 · 实时留出组 A/B

小部分对话用新回复，其余做对照组，对比真实结果。[zobi]

5 · 话术本 / skills

赢单回复模式 → 可复用 skill，靠积累不靠重训。Hermes 会自动把经验沉淀为 skill；可选 GEPA（Genetic-Pareto Prompt Evolution，ICLR 2026 Oral）离线读执行轨迹进化 skill——走 PR 审核、单次 $2–10、无需 GPU。[Nous Research]

6 · 我们自己的语料

从第一天就收集带标签对话 → 等量大了再考虑微调

不该抄的（电商专属）

  • 购物车挽回、催促、标准化商品推荐
  • 电商的 agent 能把单子全程自动化谈成；我们的业务不是电商，所以方案、报价、成交这些环节必须有真人参与，不能全自动。
  • 短周期、低介入的语气

一句话：把 Zobi 当agent 架构范本，别当行业范本。我们的 Pipedrive 结果标签 + Hermes 记忆 + n8n 留出组，就是同一套机制层——卖什么都成立。

11 结论 & 下一步

  • Zobi 的护城河是数据飞轮（跑 → 标签 → 训练 → 更强），不是提示词。
  • 我们第一天没法训模型——但能用同样的闭环（结果标签 + 话术本）跑起来。
  • 用 Hermes + DeepSeek / Kimi / 混元 先上 MVP；从第一场对话就埋好结果采集。
  • 差距是真的，但补得上：模型负责写，我们的闭环负责教。

我们的技术栈

  • CRM：Pipedrive — 记录结果：每条对话的客户动作（回复 / 预约 / 到场 / 报价）
  • Agent harness：Hermes Agent（循环、工具、skill、记忆、cron、MCP、子 agent）
  • 渠道：WhatsApp Business API · Calendly · Email
  • VPS：Hetzner（德国）走 SSH
  • 主力 LLM：DeepSeek V3 或 Kimi K3 或 混元 待确认
