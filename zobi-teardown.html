01 What is Zobi

An applied AI lab building "models with EQ" — models trained to understand and influence people.

Base

Tallinn, Estonia. Small, flat team — 8 open roles, no management layers, everyone reports to the founder.

Not a SaaS vendor

They train their own models and run sales conversations end-to-end for commerce brands. The product is the model + the loop.

The bet

"Language models learned to write by reading. The next capability is learned by trying and finding out — from consequences, not instructions."

"No model has learned to sell. Frontier models can describe a product perfectly, but they've never sat with ten thousand hesitant buyers."

03 How the AI Lab Trains Its Model

The lab's core engine: turn every live conversation into a training signal.

1 · Run
Agents run real sales chats end-to-end for brands
→
2 · Label
Each thread tagged with the outcome (what the customer did)
→
3 · Train
Train on outcomes, not text. Predict conversion per reply
→
4 · Score
Judge on revenue per conversation
↺
5 · Validate
Live holdout A/B → deploy better policy → repeat
"Trained on outcomes. Evaluated on revenue." — the model learns from the one signal the public internet lacks: what a real buyer did next.

Scoring detail: each draft reply gets a predicted chance of converting; the gap between prediction and reality flows back into training. A reply that reads best is often not the one that sold — so they never score on "looks good".

04 The Outcome Label (no human annotator)

Nobody rates replies. The label is simply what the customer did — a much harder thing to fool.

Captured per thread

  • replied — and how quickly
  • clicked the link
  • bought — for how much, discount used?
  • reordered later, or not
  • refunded

06 What the Agent Actually Learns

"Most of selling isn't in the words." — read the person from thin signals, get the timing right, know when to stop talking.

Thin signals

  • "you're the best 🙏" → thread is warm
  • "ok" → thread is cooling
  • When to mention price
  • When to follow up
  • When to go quiet

Context changes the reply

  • Loyal repeat + discount = lost margin
  • Hesitating first order, Sunday night + discount = sometimes the sale
  • Discount can win the order or cheapen the brand
  • Model learns by seeing it happen a lot — not by rules

Ethics built in: consent, tone and honesty are measured, not just guardrails — "a sale that loses you the customer isn't one."

07 The Gap: Their Model vs Our API

Zobi — owns the model

  • Trained on 1M+ outcome-labeled sales conversations
  • Learns consequences, not just text
  • Predicts conversion per reply
  • Improves from every live chat
  • Moat = data flywheel + own weights

Us — DeepSeek V3 / Kimi K3 API

  • Trained on public internet, never saw a sales outcome
  • Writes fluent sales copy, but no idea if it worked
  • No conversion prediction, no outcome learning
  • Static between our calls
  • Moat must come from our loop, not weights

The core gap: the API model lacks the outcome feedback loop. We can't retrain it — but we can build the loop around it.

08 How We Bridge the Gap

Model = the writer. Our loop = the teacher. Six concrete mechanisms:

1 · Outcome labeling

Use Pipedrive stage progression as the label. We own the loop, not the model.

2 · Revenue per conversation

North-star metric = did the stage advance / did it earn. Not "sounds good".

3 · Context via memory

Hermes persistent memory stores first/repeat, price-sensitive, channel, time of day.

4 · Live holdout A/B

n8n / workflow: only 20% get a reply change, compare the rest.

5 · Playbook / skills

Winning replies → reusable skills (GEPA-style). Accumulate, don't retrain.

6 · Our own corpus

Collect labeled threads from day 1 → future fine-tune option when volume justifies.
